# CE7454 code synchronization plan, 10 November 2026

## What is ready

A code-only overlay extends the current research/evidence tree with the E3
snapshot import, regression tests and corrected remaining-work status. It is
based on the locally retained payload for `sync/research-evidence-20261110`.
That is a verified historical source, not a fresh claim about either host's HEAD.
The overlay manifest records exact before/after hashes and refuses a conflicting
target through the accompanying read-only preflight.

No remote copy, Git commit/push, merge, service restart or GPU job was performed
for this revision. GPU04 and Spark02's strict Windows SSH routes returned
pre-authentication `Permission denied`, so their current checkout, workloads and
service status cannot be asserted from this work.

## Keep these responsibilities separate

- Research source: the CE7454 repository, with study analysis under
  `study/author_analysis/` and supplemental controls under
  `evaluate/supplemental/`. Prefer a dedicated review worktree based on the
  current verified research/evidence branch for this change.
- Immutable evidence: existing run folders, input/model locks, candidate
  outputs and completed E3/E4 receipts outside Git. Never rsync an entire
  project tree over these directories.
- Spark annotation runtime: staged/deployed portal code, its fixed public and
  private mapping, reviewer configuration and response storage. The analysis
  source is not a deployment of that portal. No data-format migration or route
  activation belongs to this overlay.
- Mobile app: retain its separate linked worktree/branch. Consolidating local
  folders does not mean merging research and app workstreams or overwriting
  uncommitted design changes.

## When authorized host access works

1. Read current hostname, repository root, commit/branch, worktrees and dirty
   status. Check active jobs and ports without stopping anything. Preserve all
   uncommitted work and frozen evidence. Verify which repository actually owns
   the target files; do not assume a historical path is still current.
2. Create/use an isolated review worktree on an appropriate new branch from the
   verified source. Do not apply directly to an actively running checkout.
3. Run the read-only overlay preflight against that worktree. It requires the
   intended repository root, clean Git status, verified overlay hashes and
   matching expected old file hashes (or an already-installed exact new hash).
   It refuses a changed target or unexpected existing new file. Never bypass
   this refusal by forcing a copy.
4. If the preflight is clean, apply only the listed code/documentation files
   through the authorized engineering workflow. Rerun all relevant research,
   supplemental and author-analysis tests in that host's Python environment.
   Recheck source/model/input locks after changes. This is not authorization to
   mutate the frozen run or produce a new study under its old identifier.
5. Compare the same code commit on the second host. Transfer only the required
   code; preserve machine-specific model caches, paths, package environments,
   portal ports, credentials, response databases and output directories.
6. Record the actual commit, host test results and remote branch verification
   before reporting synchronization complete. Publication, merging and service
   activation remain separately scoped actions.
